# Fragment shader cost reduction for masking and blur

## Scope

Reduces per-fragment arithmetic in the two framework shaders most exposed to fill rate, which is the usual limit on mobile GPUs (tile-based, low ALU throughput for transcendental functions, `mediump` evaluated at fp16). A small CPU-side cache in `BufferedContainer` is included. Vertex formats, uniform layouts, sampling positions and draw order are unchanged.

## Changes

### `Resources/Shaders/sh_Masking.h`

`getRoundedColor()` runs for every fragment drawn inside a masking container or with a blend range, so it covers most UI in rounded containers.

- `distanceFromRoundedRect()`: when `g_CornerExponent == 2.0` (the `CompositeDrawable` default) the corner distance is `length(d)` instead of `pow(pow(d.x, 2) + pow(d.y, 2), 0.5)`. Three `pow()` (each `log2` + `exp2` on most GPUs) become one `sqrt`. Other exponents keep the general path.
- Alpha exponent: the framework only sets `AlphaExponent` to 1 (masking) or 2 (edge effects). `pow(a, 1)` is skipped and `pow(a, 2)` becomes `a * a`; the hollow edge-effect inverse `pow(a, 1/2)` becomes `sqrt(a)`. Other values keep `pow()`.

All branches test uniforms only, so they do not diverge within a draw. Inputs to the replaced `pow()` calls are already non-negative, so results are mathematically identical.

### `Resources/Shaders/sh_Blur.fs`

Previously each tap pair called `exp()` and divided twice (Gaussian normalisation and `direction * x / texSize`), up to 100 times per fragment at the maximum radius.

- The `1 / (sqrt(2pi) * sigma)` constant cancels in `sum / totalFactor`, so weights are evaluated relative to the centre tap.
- For tap positions `x = i - 0.5`, `i = 2, 4, ...`, successive weights differ by a ratio that itself shrinks by the constant `exp(-4 / sigma^2)`. Weights are generated by two multiplications per step from three `exp()` calls made once per fragment.
- `direction / texSize` is computed once.
- Weight recurrence and the running total are `highp`; previously the Gaussian was evaluated at `mediump`, so precision on fp16 GPUs is equal or better.

Sampling positions (centre plus pairs at 1.5, 3.5, ...), the doubled weight convention, the loop bound/break and the Apple `g_BackbufferDraw` workaround are preserved.

### `Graphics/Containers/BufferedContainer.DrawNode.cs`

`ApplyState()` recomputed `Blur.KernelSize()` (an iterative Gaussian search) for both axes on every state application. It now recomputes only when `BlurSigma` changes. The initial state (`sigma = 0`, radius 0) matches `KernelSize(0)`.

## Verification

Run on Windows, D3D11 offline renderer:

- `dotnet build -c Debug -warnaserror osu-framework.Desktop.slnf`: 0 warnings, 0 errors.
- A temporary explicit GPU test (not committed) rendered the same scenes with the previous shaders (`git archive HEAD osu.Framework/Resources/Shaders`) and the new ones, 128x128, comparing every RGBA byte:

| Scenario | Differing pixels | Max channel difference |
| --- | --- | --- |
| Rounded mask + gradient border, exponent 2 | 0 | 0 |
| Superellipse mask, exponent 2.5 (general path) | 0 | 0 |
| Glow edge effect (alpha exponent 2) | 2 | 1/255 |
| Hollow glow (inner `sqrt` path) | 2 | 1/255 |
| Blur sigma 2.5 | 0 | 0 |
| Blur sigma 40, rotated 90 | 0 | 0 |
| Blur sigma 9, rotated 33 | 0 | 0 |

- Existing tests: `MaskingBatching*`, `TestSceneBufferedContainer*`, `TestSceneMasking*`, `TestSceneEdgeEffects`, `TestSceneBlur*`, `TestSceneBorderColour*`: 28 passed; explicit `MaskingBatchingGpuTest`: 1 passed.

## Limitations

- No Android/iOS build or device run was possible (no mobile workloads installed). GLSL ES and Metal output were not compared; desktop D3D11 evaluates `mediump` at fp32, so fp16 behaviour is argued from the precision changes above rather than measured.
- No frame-time measurement was taken. The change removes ALU work; scenes bound by texture bandwidth (large blurs) may see smaller gains than ALU-bound masking.
