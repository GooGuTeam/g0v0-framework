# 滑条无离屏路径纹理：源码研究

## 当前状态与目标

本轮已撤回参数化渐变实验，保留静态 GPU 网格、可见区间、动态端点、回放路径实例／版本同步及更早的优化。方案 A–C 为源码分析与候选设计，无运行时或性能验证；方案 D 已有可选的桌面实验实现（`DirectPathRendering = true`），见下文。

目标分为两层：

1. 消除 Ctrl+F3 中形状为整条滑条的专用 R16F 距离场纹理，不创建、清空、绘制或采样每滑条 framebuffer。
2. 严格不生成滑条纹理时，将一维皮肤渐变也放入普通 GPU 数据缓冲。主画面、离线导出和其他容器自身的目标纹理不属于滑条资源，仍按原用途保留。

不能以重命名、隐藏纹理统计，或将距离场换成另一种颜色纹理代替以上目标。无纹理不等于无数据上传；路径、空间索引和小型参数仍需 GPU 缓冲。

## 已确认的架构事实

| 源码 | 对设计的约束 |
| --- | --- |
| `Graphics/Lines/Path.cs`、`Graphics/BufferedDrawNode.cs` | 当前每条路径拥有共享的 R16F 缓冲，按绘制版本复用。完全展开且不变化的滑条可只合成缓存，不必每帧重新计算路径。 |
| `Resources/Shaders/sh_PathPrepass.fs` | 单段覆盖值为 `clamp(1 - distanceToSegment / radius, 0, 1)`。 |
| `Graphics/Lines/Path.DrawNode.cs` | 多段通过 MAX 混合合并，动态边界段与静态内部段使用同一距离定义。 |
| `Resources/Shaders/sh_Path.fs` | 先过滤距离场，再查渐变颜色，最后应用 drawable 颜色、透明度与遮罩。 |
| `Graphics/Veldrid/VeldridDevice.cs` | 主 swapchain 请求 `PixelFormat.R16UNorm` 深度，无 stencil。 |
| `Platform/SDL2/SDL2GraphicsSurface.cs`、`Platform/SDL3/SDL3GraphicsSurface.cs` | OpenGL 请求 16 位深度及 8 位 stencil，不能据此假设所有后端相同。 |
| `Platform/GameHost.cs`、`Graphics/DrawNode.cs`、`Graphics/Rendering/DepthValue.cs` | 主画面深度被前向不透明遮挡预处理占用；后向绘制默认只测试不写入。不能局部清空或重写后假设其他对象不受影响。 |
| `Graphics/Rendering/OfflineFrameRenderer.cs` | 离线导出目标仅有颜色附件，绘制时禁用深度；普通 BufferedContainer 的默认目标也不要求深度／stencil。 |
| `Graphics/Rendering/Renderer.cs` | 现有 `Clear()` 同时面向颜色和深度等附件，且禁用 scissor 后清理；不能拿它直接做保留画面的局部临时深度重置。 |
| `Graphics/Rendering/IRenderer.cs` | 有 SSBO／UBO 数组接口，UBO 安全预算为 16 KiB，shader 两种声明必须匹配。 |
| `Graphics/{OpenGL,Veldrid}/Buffers/*ShaderStorageBufferObject.cs`、`Graphics/Rendering/Deferred/DeferredShaderStorageBufferObject.cs` | 现有数组接口为可写缓冲，后端上传、零值跳过及释放方式不同；Deferred 当前直接分配 structured buffer。不能自动视为已满足新静态路径资源的不可变性和延迟释放契约。 |

McOsu 参考仍固定为 `db2add20ea291f6f3b6d022fcd4eba100a5bd161`：普通桌面 `OsuSliderRenderer::draw()` 使用深度测试、关闭混合并绘制到滑条 framebuffer，再透明合成。`drawVR()` 使用双网格及特殊混合；`sliderVR.fsh` 明确记录无 FBO 时边框内侧平滑受限。仅借鉴设计，禁止复制 GPL 源码、shader 或网格。

## 方案比较

### A. 深度预处理＋着色去重

候选流程：关闭颜色写入，以径向距离写深度；再使用相等深度测试着色，并以 stencil 防止相同深度的多个片元重复混合。

必须解决：

- 单次边画边写深度仍会把多个先后通过测试的半透明片元混合到背景，无法撤销早先颜色。需要先完成覆盖选择。
- 相等深度并不能单独去重：共线重复段、共享端点、零长度段及深度量化都会产生相等深度。缺少 stencil 或其他所有权规则时仍会重复合成。
- 当前主画面的深度内容不能被当成临时空间覆盖；为滑条独立换深度附件，需要新的目标视图／状态管理，并处理原有遮挡关系。
- Veldrid 主目标没有 stencil；离线导出及嵌套缓冲连深度也可能没有。改成全目标附加深度／stencil 会扩大内存与后端修改范围。
- 直接在片元 shader 写距离深度可能抑制 early-Z，且 16 位深度精度、重复段和接缝需要验证。

结论：理论可行，但至少有多次绘制、临时附件管理和遮挡集成成本，当前不作为首选。单独启用 stencil 并保留第一个片元也不正确：第一个片元未必来自最近的线段。

### B. 路径并集三角化／最近线段区域划分

将路径描边生成无重叠网格，或构造最近线段的区域划分，每个像素只由一个区域着色。

优点是片元计算少，无共享深度状态要求。困难是自交、近共线、退化段及精确圆帽处理；蛇入／缩尾移除线段会改变最近线段区域，不能只对完整并集做简单的索引区间裁剪。单纯画一条 triangle strip 无法解决自交。

结论：静态全路径有潜力，任意可见范围下的稳定拓扑与缓存设计成本高。

### C. 不重叠空间块＋局部距离求值（优先研究）

将可能被路径覆盖的空间划分为互不重叠的 quad；每个片元读取本块相关的可见线段，计算最小距离，随后只进行一次最终颜色混合。路径形状保存在 GPU 数据缓冲中，整个过程不创建滑条纹理。

几何层面的依据：对正半径及同一组线段，

```text
max_i clamp(1 - distance(p, segment_i) / radius, 0, 1)
    = clamp(1 - min_i distance(p, segment_i) / radius, 0, 1)
```

这等价于当前理想距离场的覆盖合并。它不自动等价于经过三角形栅格化、R16F 量化和双线性采样后的最终像素。

## 方案 C 的实现草案

### 静态数据

- 完整采样路径及原始段编号；零长度段按点距离计算，禁止直接除以零。
- 路径局部空间中互不重叠的网格单元，仅保留与半径膨胀后的线段相交的单元。长段应使用保守的网格遍历，避免枚举巨大斜线 AABB 中的所有空格。
- 每单元的候选段编号列表及空间范围；密集处可使用分层索引。候选判断需覆盖整个胶囊段，不能只看端点，也不能截断到固定 K 条后静默丢弃。
- 静态单元 quad 网格可以复用已有 `StaticQuadMesh<T>` 基础设施，但其几何含义与当前逐线段 quad 不同。
- 路径和索引缓冲采用初始化一次、引用期间不可变、替换时新建、延迟销毁的契约。需提供与 Deferred 事件兼容的资源引用；不能将旧帧仍使用的缓冲原地覆盖。

### 每帧可见范围

- 上传起止范围、插值端点、半径／变换和合成颜色，不重建完整路径。
- 内部完整段按 `PathDrawRange` 对应的原始段编号筛选。
- 两段边界连接应纳入同一次最小距离求值，不能再以独立透明 draw 补端点；否则它们与内部路径的交叠会再次混合。
- 当区间没有中间顶点时，保留起止插值点之间的边界段；所有完整段被过滤后也不能漏掉这一段的覆盖单元。
- 端点段属于原路径的局部部分，完整路径的保守空间覆盖可以复用；仍须显式处理空路径、单点和零长度退化情况。
- 不对不同滑条重排或一起取距离最小值。每条滑条保持原 draw order，跨滑条透明重叠保持原样。

### 最终着色与资源

- 每单元只在本条滑条中覆盖一次。所有单元共享一致的边界坐标和三角形边缘规则，内边界不独立淡出或向外膨胀；需防止接缝漏像素及重复合成。
- 在局部空间计算距离，按现有变换映射到当前渲染目标；正确接入 drawable 颜色、屏幕空间遮罩、backbuffer draw depth。保留原有深度测试状态，不额外写入场景深度。
- 初始着色可把原 `ColourAt()` 的 RGBA8 样本写入小型只读数组缓冲，手动做两点插值。这样保留任意皮肤渐变定义，不恢复已撤回的参数化皮肤公式，也不创建一维纹理。颜色或半径改变时仍有小型 CPU 数据生成和上传。
- 数组缓冲的采样宽度、RGBA8 量化和 clamp-to-edge 语义沿用 SmoothPath。buffer fetch 不等于免费，需要计入 GPU 工作量。
- `Path` 当前通过 `FrameBufferDrawColour` 把真实颜色留给合成节点，子节点返回白色。绕过 BufferedDrawNode 时必须重新接上真实颜色及透明度，否则会丢失淡入、Hidden、父级颜色等效果。

### 尚未解决的兼容与性能问题

1. **密集曲线**：每片元遍历 K 个候选的开销约为 `sum(block_pixels * visible_candidates)`，不保证优于当前逐段 MAX 混合。大量重叠短段可能使 K 接近全路径大小。可研究带原始编号范围的 BVH 裁剪，但遍历、寄存器和分支发散也有成本。
2. **无 SSBO 后端**：UBO 分页必须保证一个片元能获得全部相关候选。将同一单元的不同分页分别透明绘制会破坏最小距离合并；单纯缩小单元也无法保证复杂自交处候选数低于上限。需要明确的多缓冲／分层访问方案，不能依赖旧 FBO 静默回退掩盖缺口。
3. **抗锯齿与过滤**：旧流程先在离屏像素中心量化距离，再双线性过滤距离，最后查颜色。直接在当前片元求距离会改变边缘。若要求接近逐像素一致，需研究复现旧离屏网格的相邻四个距离样本及量化，候选范围也须覆盖这些样本；成本可接近四倍。`fwidth` 抗锯齿是另一种外观选择，不能宣称与旧输出严格相同。
4. **静态缓存优势丢失**：当前不变化的滑条可以重用距离场；直接方案每帧重新求距离。潜在收益集中在减少 FBO 切换、清理、形状纹理占用和动态重绘，完全展开的滑条可能反而更慢。
5. **尺度和极端坐标**：非均匀缩放、旋转、镜像、巨大屏外路径、有限浮点精度及可见区间为空都要有明确规则；只裁剪完整单元，不能让端点越界改变几何。
6. **后端资源实现**：OpenGL、Veldrid、Deferred 的缓冲绑定／生命周期需分别落地。现有 ShaderStorageBufferObject 的接口能表达读取，但初始化和销毁契约需要专门设计；尤其不能漏掉初始全零数据。

## 方案 D：按 osu!droid 思路的深度分层网格（桌面实验）

`DirectPathRendering = true` 时，`SmoothPath` 改由 `Path.DirectDrawNode.cs` 直接绘制到当前目标，不创建滑条 framebuffer：

- 渐变取自生成渐变纹理的同一组字节，按纹素中心位置排列，拟合为距离上线性变化的若干色带；每带线性误差不超过 1.5/255，颜色变化不超过 0.125，超过 16 带则回退。
- 每个色带是一组屏幕空间网格：每段两侧各一个四边形，外侧拐角与两端为圆弧扇环。所有色带共用最外圈的圆弧细分，相邻色带顶点完全重合，避免裂缝。
- 色带由内向外绘制，开启深度写入与 `LessThan`，深度值每条路径每帧唯一且递减。每个像素只被覆盖它的最内色带写入一次，自重叠不会重复混合；后绘制的路径深度更小，仍覆盖先前的路径。
- 顶点着色器 `sh_PathDirect.vs` 以 `G0V0_DRAW_DEPTH_ALWAYS` 包含 `sh_Texture2D.vs`，在 framebuffer 中同样写入深度；离线导出目标在开启变量时附加 D16。
- 回退条件明确：目标无深度附件、深度测试已开启（前后向遍历）、颜色为渐变、或路径没有 `DirectGradient`，此时仍走原 framebuffer。

与方案 A 的区别：不需要深度预处理和 stencil，代价是同一色带内的自重叠像素取先绘制线段的颜色，而非最近线段，误差以色带颜色变化为上限。

桌面验证（离线基准，1920×1080，Argon 皮肤，Release，Veldrid）：

- 像素：帧 120–900 的滑条区域与 framebuffer 路径一致，仅抗锯齿边缘有差异，最大 20/255，超过 8/255 的约占滑条像素 0.2%；两次基线运行在这些区域完全相同。framebuffer 路径对距离场做线性重采样，边缘略软。对比中发现并修复两处问题：各色带圆弧细分不同造成的裂缝，以及渐变半个纹素的偏移。
- 绘制调用：每条滑条一次。第 262 帧共 36 次绘制（原 38 次），两条蛇形滑条共 5,884 个顶点，取代 framebuffer 重绘与合成。
- 帧时间：差异在噪声范围内。成对轮次的中位差为 +0.01 ms 与 +0.13 ms（5 轮、8 轮），帧时间约 3.6 ms。网格每帧在 CPU 上重建，抵消了桌面 GPU 上省下的开销；目标收益在 tile 架构 GPU 的渲染通道拆分上，需在设备上测量。下一步可在路径、可见区间、矩阵与颜色不变时缓存网格。
- 未覆盖：带渐变的皮肤（Argon 滑条主体为纯色）、legacy 皮肤、遮罩、GL 渲染器、窗口实机及任何设备。

## 下一步建议

先明确方案 C 的数组缓冲容量、密集候选完整性及边缘过滤规则，再实现独立的直接渲染节点。若无法满足所有目标后端，应明确报告限制，不添加不透明的 FBO 回退。

当前阶段仅完成源码研究和渐变实验回退。未添加或运行测试、shader 探测、应用或基准；后续如获授权验证，应分别观察复杂自交、零长度、双向缩尾、回放跳转、不同皮肤、嵌套缓冲和离线导出，记录 CPU Draw／GPU 时间、FBO 重绘／切换及显存，而非只看纹理检查器或平均 FPS。
